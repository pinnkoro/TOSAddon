# スキル錬成の振り直し（skill_reroll）

> スキル錬成（素の `common_skill_enchant`）を、希望スキルが出るまで自動で回す

| 項目 | 内容 |
| --- | --- |
| 設定キー | `skill_reroll` / `skill_reroll_auto_open` / `skill_reroll_presets` |
| ソース | [core.lua](core.lua) / [window.lua](window.lua) / [run.lua](run.lua) |
| 設定画面 | 「自動処理関連」セクション（ON / OFF） |
| 保存先 | プリセットは `mini_addons.json` の `skill_reroll_presets`（配列） |

## ファイル

| ファイル | 内容 |
| --- | --- |
| [core.lua](core.lua) | 定数と内部関数の入れ物（`local skill_reroll`）・アイテムと候補の読み出し・素の錬成ボタンを「停止」にする処理・素の窓への追随 |
| [window.lua](window.lua) | 自前の窓の中身（希望スキルのチェックと最低レベル・リピート回数）とプリセットの保存 / 読込 / 削除、素の窓への「高度な設定」ボタン |
| [run.lua](run.lua) | 連続実行。結果を見て、要らない候補は「維持」で捨て、もう一度撃つ |

## 使い方

1. スキル錬成の窓を開くと、タイトルの × の左に **「高度な設定」** ボタンが出ます（押すたびに開閉）。
   `skill_reroll_auto_open` が ON なら、アイテムを乗せた時点で自動で開きます。
2. 欲しいスキルにチェックを入れます。右のボタンが**最低レベル**で、左クリックで 1 つ上がり
   （上限の次は `Lv1` に戻る）、右クリックで 1 つ下がります。**`Lv1` はレベルを問いません**
   （スキルのレベルは 1 からなので、「1 以上」と「不問」は同じ意味です）。
   見出しの右の **「全解除」** で、チェックを一括で外せます（確認を挟みます。
   最低レベルの設定は残るので、入れ直せば前の値がそのまま戻ります）。
3. リピート回数を決めます（`ALL` ボタンで手持ちの素材で回せる回数が入ります）。
4. 素の「スキル錬成」ボタンで開始。回している間は同じボタンが **「停止」** になり、
   その上に**残り回数**が出ます。

プリセットはドロップリストから選ぶと**その場で読み込みます**（読込ボタンはありません）。

## しくみ

素のスキル錬成は 3 状態しかありません（素の `COMMON_SKILL_ENCHANT_CHECK_EQUIP_STATE`）。

| 状態 | 中身 | 「スキル錬成」を押すと |
| --- | --- | --- |
| 0 | スキルが付いていない | 素材を使ってスキルが 1 つ付く（候補は出ない） |
| 1 | スキルが付いていて候補が無い | 素材を使って**候補**が出る |
| 2 | 候補が出ている | 押せない。「維持」か「変更」を選ぶまで進めない |

そのため振り直しは **「撃つ → 候補を見る → 要らなければ維持で捨てる → また撃つ」** の
繰り返しで、1 周につきサーバとのやり取りが 2 回あります。

* 当たり判定は**候補**（`CommonSkillStr`）を見ます。候補が無いときだけ、今付いている
  スキル（`EnchantSkillName_1` / `EnchantSkillLevel_1`）を見ます
  （状態 0 のアイテムは 1 回目でいきなり付き、候補が出ないため）。
* 希望スキルが出たら**止めて確認ダイアログ**を出します。「いいえ」なら候補はそのまま
  残るので、素の「変更」/「維持」で決められます。「はい」なら**その当たりを見送って**
  もう一度回します（見送った印は指紋で持つので、同じ確認を出し続けません）。
* 次を撃つのは**結果が返ってから**です。合図は素の `COMMON_SKILL_ENCHANT_END`
  （0.8 秒の演出の終わり）と、演出を出さない「維持」の `SUCCESS_COMMON_SKILL_ENCHANT`
  （`arg_num == 2`）の 2 つ。
* 素材の判定は素の必要量表（`shared_common_skill_enchant.get_cost`）から数えます。
  足りなくなったらリピート上限に届いていなくても止まります。

## 注意

* **素の関数をそのまま呼ぶこと。** 撃つのは素の `COMMON_SKILL_ENCHANT_DO`、候補を捨てるのは
  素の `COMMON_SKILL_ENCHANT_SELECT_BTN_LEFT`。`ReqExecuteTx_Item` を自分で組み立てると、
  引数（現状 `"1 1"` / `"1 2"`）が素で変わったときに黙って古いままになります
  （CLAUDE.md「素の関数を書き写さない」）。
* **`SetColorTone` は使わないこと。** 素の錬成ボタンを「停止」にするときは、キャプションを
  控えて入れ替えます（キャプションを持つコントロールでは ColorTone を元に戻せません）。
* **この窓は ESC のスタックへ積まないこと。** 素の窓に貼り付いている付属パネルなので、
  CLAUDE.md の例外に当たります。積むと素の `COMMON_SKILL_ENCHANT_CLOSE` が持っている
  後始末（インベントリの右クリック割り当てを戻す）を奪ってしまいます。
* **回している間は錬成ボタンを押せる状態へ戻し続けること。** 素は結果のたびに
  `REFRESH_COMMON_SKILL_ENCHANT` で `do_enchant:SetEnable(0)` を掛け、候補が出た状態
  （state 2）では素材の一覧を組み直さないので誰も戻しません。見張り（0.3 秒）任せだと
  1 周ごとに「停止と書いてあるのに押せない時間」ができます（実際に報告されました）。
  今は tick（0.1 秒）・素の `REFRESH` / `SET_TARGET_ITEM` のフックからも通しています。
* **最低レベルは数値入力にしないこと。** 取りうる値は 1〜5（一部 1〜3）しかありません。
  素にスライダー（`slidebar` / `ui::CSlideBar`）はありますが、**上限 / 下限はどれも XML の
  `maxlevel` / `minlevel` で決めていて、Lua から設定している箇所がクライアント全体に
  ありません**（`SetLevel` / `GetLevel` だけ）。プログラム生成では範囲を絞れないため、
  押すたびに 1 つ動くボタンにしてあります。
* **チェックのイベントで渡ってくる `ctrl` を当てにしないこと。** 実機で、押した行とは
  別の行のコントロールがイベントを受け取ることがありました（アインソフを押したのに
  `Common_Chronomancer_Pass = OFF` が届き、画面はアインソフにチェックが付いたまま）。
  コントロール名から希望スキルを決めていたため、**画面に入っているのに表には無い**
  チェックができ、全解除の件数が合わないうえ**当たっても止まらない**状態になりました。
  今は `skill_reroll.sync_from_screen()` で一覧全体を画面から読み直し、
  チェックしたとき・数える前・回し始める前・保存する前に必ず通しています
  （どのコントロールがイベントを受けても結果が同じになります）。
  最低レベルのボタンも、名前ではなく作成時に持たせた `CLASS` を見ます。
  あわせて**行の送りを広げてあります**（`skill_reroll.ROW_STEP` = 32 / チェックボックスの
  高さ 22）。当たり判定が縦に重なっているのが疑わしいためで、狭めるときは実機で確認を。
* **回す対象は開始時に固定する。** 回している最中でもインベントリの右クリックや
  ドロップで素はスロットを差し替えられるので、見ていないと**乗せ替えた別のアイテムを
  黙って回して素材を溶かす**ことになります（`TARGET_GUID`）。
* **結果待ちのまま止めるときは `ui.SetHoldUI(false)` を呼ぶこと。** HoldUI を掛けるのは素の
  `COMMON_SKILL_ENCHANT_DO` / `SELECT_BTN_LEFT` で、解くのは素の SUCCESS / FAILED だけです。
  結果が返らない経路ではどちらも走らないので、掛かりっぱなしになると素の
  `CLOSE` / `REFRESH` / `SET_TARGET_ITEM` が揃って `ui.CheckHoldedUI()` で即 return し、
  **やり直すことも窓を閉じることもできなくなります**（後始末は `skill_reroll.stop` が持つ）。
* **素の錬成ボタンのフックは置換方式（`g.setup_hook`）にすること。** イベント方式の
  `bool=false` だと、Mini Addons を OFF にしたときに `Mini_addons_teardown` が購読だけ外して
  ラッパを `_G` に残すため、素の「スキル錬成」ボタンが誰も呼ばない no-op になります。
* **内部関数と定数は `local skill_reroll = {}` にまとめること。** bundle 全体が 1 つの
  チャンクとして読まれるため、トップレベルの `local` は既に上限（200 個）際です。
  並べて足すと、**関係の無い所で丸ごと読み込めなくなります**（実際に踏みました）。
* **結果が返らないときに撃ち直さないこと。** 遅れているだけだと、まだ飛んでいる 1 発と
  重ねて撃つことになり、当たった候補を次の結果で潰します。見張りタイマーは**撃たずに
  止めて知らせる**方に倒してあります。
