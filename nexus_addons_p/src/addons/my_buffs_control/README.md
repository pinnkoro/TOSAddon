# My Buffs Control

> バフ欄を移動可能にして、選択したバフを非表示にします（街では動作しません）

| 項目 | 内容 |
| --- | --- |
| キー | `my_buffs_control` |
| ソース | [my_buffs_control.lua](my_buffs_control.lua) |
| 設定画面 | あり（アドオン一覧の歯車ボタン） |

## 使い方

ON にすると、自分のバフ欄（`buff` フレーム）の左上に**鍵アイコン**が付きます。

| 操作 | 動作 |
| --- | --- |
| 鍵アイコンを左クリック | ロックの ON/OFF。解除するとバフ欄をドラッグで移動できる |
| バフ欄をドラッグ | 移動。離した位置が保存される |

### 表示するバフを選ぶ

アドオン一覧（メニューボタン → アドオン一覧）の歯車ボタンから設定画面を開き、
**「Buff list」ボタン**を押すとバフ一覧が開きます。

* チェックが入っているバフだけが表示されます。**チェックを外すと非表示**になります。
* 検索欄で名前を絞り込めます。
* チェック済みのバフが一覧の上に来るよう並べ替えられます。

設定画面の **「Default Pos」ボタン**でバフ欄の位置を既定（`20, 130`）に戻せます。

## しくみ

* 素の `BUFF_ON_MSG` を**置換方式**（`g.setup_hook`）で差し替え、**素を呼ぶかどうかだけを決めます**。
  表示するバフ・デバフ・セパレートバフ欄行きは素へそのまま渡し、非表示指定のバフは
  **素を呼びません**（＝バフ欄に描かれない）。素の中身は写していません。
* 以前は「素に描かせてから `COMMON_BUFF_MSG` に `REMOVE` を投げて取り消す」作りでした。
  自分のバフ欄は素が状態を積み上げて描く（`ADD` は空きスロットへ入れ、`REMOVE` は後ろを
  繰り上げる）ので「並べるところで飛ばす」入口が無く、後追いで消すしかなかったためです。
  そのぶん非表示のバフ 1 個につき素の再配置（`ARRANGE_BUFF_SLOT`）が 2 回走っていました。
* **例外は「非表示にする前から出ていたバフ」だけ**です。レイド中に設定画面でチェックを
  外しても、既に出ているアイコンは残ります（過去のメッセージは戻ってこないため）。
  そのときだけ `My_buffs_control_is_displayed` で確かめて、素に `BUFF_REMOVE` として
  処理させます。出ていなければ何もしません。
* 初期化時（およびその 1 秒後）に、現在表示されているバフと実際に付いているバフを突き合わせます。
  ログイン直後やマップ移動直後に取りこぼしが出ないようにするためです。
  * **差分を 1 件ずつ埋めるのではなく、一度 `CLEAR` して表示するものだけ並べ直します。**
    素の `COMMON_BUFF_MSG("REMOVE")` は 1 回ごとに `ARRANGE_BUFF_SLOT` まで通るので、
    街から持ち込んだ非表示バフを 1 件ずつ落とすと「非表示の数 × フル再配置 × 2 回」に
    なります（街ではすべて表示するため、レイド入場時は全部が対象になります）。
  * 今の並びとあるべき並びが**一致していれば何もしません**。1 秒後の呼び直しは
    通常ここで帰るので、入場のたびに 2 回組み立て直すことはありません。
* バフ表は**非表示リスト**です。**表に載っていないバフは表示**で、`.dat` に書くのは
  利用者が実際に隠したバフ（`0`）だけです。
  * 以前は「`1` なら表示」の**許可リスト**でした。表示するバフ全部を持つ必要があるため、
    起動時に `GetClassList("Buff")` を全件舐めて `1` を入れており、`.dat` は実測
    **3816 行 / 40KB**（2026-08 の JP クライアント）。さらに未登録のバフを受けるたびに
    `1` を足して、次のマップ移動で全件書き直す経路まで生えていました。
  * 非表示リストなら書く量は隠したぶんだけ（普通は数件〜数十件）で済み、
    「初めて見たバフを表へ足す」処理（`BUFF_ADD` の購読）自体が不要になります。
  * 許可リスト時代の `.dat` は、**初回の読み込みで `0` の行だけ拾って 1 回書き直します**。
    移行のために `ver` は上げません（上げると設定ごと既定値へ差し替わり、
    利用者の位置とロック状態まで初期化されるため）。
* **デバフ（`Group1` が `Debuff` / `Deuff`）は設定に関係なく常に表示**します。
* **セパレートバフフレームに出るバフ**（`BUFF_CHECK_SEPARATELIST`）には手を出しません。
* 位置は「街用（既定位置）」と「街以外用（保存位置）」を分けて持っており、
  街に入ると既定位置に戻ります。

## 保存先

| ファイル | 内容 |
| --- | --- |
| `../addons/_nexus_addons_p/<アカウントID>/my_buffs_control.json` | 位置とロック状態 |
| `../addons/_nexus_addons_p/<アカウントID>/my_buffs_control.dat` | **非表示にしたバフだけ**（`<バフID>:::0` の行）。載っていないバフは表示 |

```json
{ "lock": true, "default_x": 20, "default_y": 130,
  "custom_x": 20, "custom_y": 130, "ver": 1.2 }
```

バフの設定だけ `.dat` に分けてあるのは件数が多いためです。
初回のみ、旧 `my_buffs` アドオンの `../addons/my_buffs/settings_2503.json` から引き継ぎ、
そこに無いバフは「表示」で埋めます。

## 注意

* **街（`City`）では何もしません。**バフ欄は既定位置に戻り、すべてのバフが表示されます
  （設定画面にも赤字で注意書きが出ます）。
* 新しく出会ったバフは自動的に「表示」として登録されます（`My_buffs_control_BUFF_ADD`）。
  判定は「表に登録が無い（`nil`）」で行うので、**非表示は `nil` ではなく `0` で持つこと。**
  `nil` にすると `.dat` から行ごと消えて「知らないバフ」に見えるため、受け直すたびに
  表示へ戻され、さらに `is_change` が立って次のマップ移動で `.dat` を全件書き直します
  （バフ表はデバフ以外のほぼ全クラスぶんあり、実測 3816 行 / 40KB）。
* 設定ファイルの `ver` が 1.2 未満のときは、位置とバフ設定をすべて初期化して作り直します。
* 本家 Nexus Addons など、同名の旧初期化関数（`MY_BUFFS_ON_INIT`）を持つ
  アドオンが読み込まれている場合は、競合を避けるため初期化をスキップします。
